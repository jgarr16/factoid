INSIGHT

Anthropic engineer on why coding agents are quietly turning you into a manager

Source: The Code, Superhuman

Surprise promotion. Your job title might still say “software engineer,” but your coding agents think you’re the boss now. In a new essay, Anthropic’s Addy Osmani argues that working with agents looks a lot like managing a team. You hand out tasks, give instructions, check progress, review the work and decide what ships. The devs getting the most out of agents are the ones who’ve quietly become good managers.

Here’re 10 major insights from his essay:

  • Give every agent a way to check its work with tests or screenshots, or you will end up validating everything yourself.

  • Tell the agent what the code cannot show it, like your overall goal, constraints, and definition of done, and skip what it can already read.

  • Whenever you correct the same mistake twice, record it in CLAUDE.md or a shared skill so your fix actually compounds over time.

  • Let the agent make most calls on its own, and save hooks or deny rules for the few things that must always or never happen.

  • Agree on a solid plan before coding starts, and split parallel work carefully so five agents do not create one giant merge conflict.

  • Steer the agent in the first minute, and if it fails after two corrections, just wipe the slate clean with a fresh session and a better prompt.

  • Delegate the work but never your judgment, and review every single diff like you are the one getting paged for it.

  • Before any unattended run, define what done looks like, how the agent verifies itself, its limits, and who approves the output.

  • Scale agents only as fast as your checks and reviewers can keep up, and track quality and rework instead of the share of AI-written code.

  • Agents make code nearly free to build, so saying no matters a lot more now that review and validation are the real bottlenecks.

AI CODING HACK

How to audit your codebase every time a new model ships

An Anthropic engineer shared the prompt he runs on every project when a new model drops. Newer models catch bugs, dead code, and bad patterns the old one missed, but almost nobody re-checks shipped code.

  • Step 1: Open Claude Code in the project root and switch to the newest model:
/model
  • Step 2: Paste the prompt:
Read this entire project and find everything that's broken, inconsistent, inefficient, or no longer needed. Fix what you're sure about and list the rest for me to review.
  • Step 3: Review the “not sure” list before committing anything.

Pro tip: save the prompt to .claude/commands/audit.md, then run /audit on every model release.
