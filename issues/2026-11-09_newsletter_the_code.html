So where is all that money going? Once a cap is in place, you need to know where your tokens go. Coding agents are set up to give you the best possible answer, which often means using more tokens than a task needs.

Three defaults drive most of that spend.

  • Subagents run at the same effort level as your main session.

  • The same top model handles everything, from planning a feature to renaming a variable.

  • The model reads every line of every log you give it, including the noise.

Each one takes a few minutes to change. Claude Code’s “/usage” command now shows you what’s draining your limit, and the 3 workflows below help you fix each default one at a time:

WORKFLOW #1: EFFORT LEVELS

How to make your Claude Code limits last the whole week

Source: X.com/bcherny

You hit your usage limit on Wednesday. You still have half the week ahead of you, and there is no clear way to tell which session burned through it.

Most of the time, the leak is your subagents. They copy your main session’s effort level by default, so if you work at max effort, every subagent you spawn runs at max effort too.

Claude Code’s creator warns that this can add up fast, and the fix is to find the leak with “/usage” and turn your subagents’ effort down.

Here’s how you can implement it:

  • Step 1: Update Claude Code and run “/usage” to see what’s using up your limit.

  • Step 2: Press “f” to apply the fixes it can make for you, then handle any rows it leaves for you to fix.

  • Step 3: Add an “effort” line, like “effort: medium”, to each subagent file in “.claude/agents/”, so your subagents run at a lower effort than your main session.

WORKFLOW #2: MODEL ROUTING

How to cut your cost per PR without losing quality

Source: X.com/zachlloydtweets

Your agent uses the same expensive model to plan a feature and to rename a variable, so even simple work bills at top prices.

Let a strong model plan the work and a cheaper model carry it out. Warp’s founder cut his team’s cost per PR from $80 to $20 this way, with fewer reverts and more PRs shipped.

Here’s how you can implement it:

  • Step 1: Set your main session to a strong model with “/model”, like Opus 5.5. That’s the model that plans the feature.

  • Step 2: Create “.claude/agents/executor.md” in your repo so a cheaper model makes the edits:

---
name: executor
description: Use proactively for plan steps
tools: Read, Edit, Grep
model: haiku
---
Make the edits for the step you are
given. Never change the plan or touch
files outside it.
  • Step 3: Ask Claude for a plan, then tell it to “use the executor subagent for each step.” Compare your cost per PR before and after the switch, and watch for reverts.
WORKFLOW #3: FILTER FIRST

How to run an agent over millions of rows without blowing your budget

Source: X.com/karpathy

Last weekend, OpenAI co-founder Andrej Karpathy built a better YouTube feed out of 43 million Hacker News comments.

Karpathy, who joined Anthropic earlier this year, didn't just dump all that data into a model.

Instead, he first filtered the comments using URL matching, regular expressions, and basic spam removal. Only then did he have Claude Sonnet read what was left.

About two hours later, he had a curated list of 6,454 videos that Hacker News users consistently recommend.

You can use this exact same approach on any large log or dataset.

Here’s how you can implement it:

  • Step 1: Before any model call, ask your agent to write a filter script:
Write a script that filters [data] down to only the rows that could matter for [question]. Use regexes, URL matching and dedupes. Don't call a model. Print the row count before and after.

  • Step 2: Check the before-and-after count, and tighten the filter if too much is left.

  • Step 3: Switch to a cheaper model with “/model sonnet”, then ask Claude to read the filtered file and answer your question.
