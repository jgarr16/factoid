🧑💻 Always-on agents: A secret tool for devs

Welcome back. Grok Bot gave engineers an early look at what an always-on agent can do, and major labs are quickly following suit. Meta released Muse, OpenAI launched Dots, and Anthropic just opened a preview of Claude Duet.

In this issue, you’ll find 3 workflows that devs are running with these agents, plus more fun projects to try. Let’s get started:

Today’s Brief

  • What is an always on agent

  • Workflow #1: Let your agent proactively check incidents

  • Workflow #2: Run Claude Code inside your Muse

  • Workflow #3: Plug Muse into any API

DEEP DIVE

Click here to watch how the new personal agents compare side by side.

What it is. A personal agent is an assistant with its own computer in the cloud, so it keeps working after you close your laptop.

How it works. You message it from your phone or Slack, it hands the coding work to Codex, Cursor, or Claude Code, and it pings you when there’s something to review.

So, which one should you pick? Start with the one that sits next to the coding tool you already use: dots for Codex, Grok Bot for Cursor, and Muse if you’re happy to set up Claude Code yourself, which we’ll walk through in Workflow #2 (see a side-by-side comparison).

The one thing to know before you connect your repo is that these agents hold your logins, so give each one only the access it needs and keep the merge button for yourself.

Here are 3 workflows worth trying out this weekend:

WORKFLOW #1: ON-CALL

How to know if a 3AM incident is real without opening your laptop

Source: X.com/@OpenAIDevs

Your phone buzzes at 3 a.m. with an incident alert. You open your laptop half asleep and start digging through logs before you even know if it’s real.

A dot can do that first look for you. OpenAI’s own demo shows how this works: it investigates the incident and starts a Codex thread with what it found, so the engineer can steer the fix from his phone.

Here’s how you can implement it:

  • Step 1: Add your dot to the Slack or Teams channel where your alerts land.

  • Step 2: Set up a Codex cloud environment with your repo, since that’s where your dot runs code work.

  • Step 3: Add a custom rule so it asks before acting, then give it a standing instruction:

When an incident lands in this channel, investigate it and start a Codex thread with what you find. Message me a short summary. Never merge, deploy or roll back without asking me.

WORKFLOW #2: CLAUDE CODE IN MUSE

How to start a Claude Code job from a text on your phone

Source: X.com/@viticci

You think of a fix while you're away from your desk, but your repo, tools, and Claude Code setup all live on your laptop. So the idea waits until you get back.

Muse runs on its own Linux computer in the cloud, so you can set up Claude Code there once and then send it jobs from a chat. One developer runs his own instance this way, and he signs in to Anthropic himself, so Muse never sees his password.

Here’s how you can implement it:

  • Step 1: In Muse chat, ask it to install Claude Code “so it persists” across restarts.

  • Step 2: When Muse opens Anthropic’s sign-in page, take over the browser and log in yourself.

  • Step 3: From your phone, send Muse a job like this one:

In the api repo, run claude -p with --permission-mode acceptEdits to fix the flaky signup test on a new branch.
Message me the diff. Never push to main.
WORKFLOW #3: CUSTOM CONNECTORS

How to connect your agent to the internal tools no one supports

Source: X.com/dps

Your status page, admin API, or niche dev tool never shows up in an agent’s connector list, so every morning you check each one by hand.

Muse can write its own connector for any service with an API, then run it on its cloud computer. A senior engineer tested it against other agents and called this the win: “any API, and it writes the script.”

Here’s how you can implement it:

  • Step 1: Ask Muse to build a connector for the service, and follow its walkthrough.

  • Step 2: When it asks for a key, use the secure input it pops up and never paste it into the chat. Start with a read-only key.

  • Step 3: Put it on a weekday schedule and check the tool-call log on the first few runs:

Every weekday at 9am, call our status API, list anything failing since yesterday, and message me a short summary. Don't change anything.
