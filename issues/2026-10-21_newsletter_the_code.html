Why Uber’s “new” AI coding stack is actually a decade old

Source: The Code, Superhuman

Ten years overnight. Uber's AI coding tools might look like an overnight win, but building them took a decade. On a recent podcast with veteran engineer Gergely Orosz, Distinguished Engineer Uday Medisetty explained how all that preparation finally paid off. Today, Uber's background coding agent, Minion, ships roughly 15% of the company's production PRs. Keep in mind, engineers built much of that essential foundation long before LLMs even existed.

Old stack, new tricks. Minion runs on DevPods, the cloud dev boxes Uber started building in 2017. A DevPod spins up in seconds, with repos cloned, build caches warm, and AI tools installed. The MCP Gateway came together quickly for a similar reason. Uber already kept service API contracts in one registry, so it could automatically turn those contracts into agent tools.

Check yourself. An agent that writes code also needs a way to test it. At Uber, agents deploy their branches to Slate, a private staging setup that routes a test account through the changed code. Even that relies on older infrastructure, Jaeger tracing. Without Slate, Medisetty says, agents would have had a much harder time validating their work.

Boring pays off. You probably don’t need Uber’s entire platform, but you can borrow the groundwork:

  • Give your agent one build-and-test command, documented in a top-level CLAUDE.md or AGENTS.md.

  • Set up cloud workspaces with repos cloned and caches warm.

  • Keep API contracts in one registry so you can generate agent tools from them.

  • Give agents a safe way to test a branch end to end before merging.

Fix the first layer that fails. Orosz's key takeaway is that the companies benefiting the most from AI already had dedicated developer platform teams in place, which was certainly true for Uber. In addition, the episode post maps out each system alongside detailed timestamps.

AI CODING HACK

How to make Claude Code chart your numbers

A developer shared a project rule that fixes a common vibe-coding annoyance. AI-built dashboards render stats as dead numbers with no trend, no context. One paste fixes every future screen.

  • Step 1: Open Claude Code in your project and send this (full rule in the tweet):
Add the rule below to this project's instructions: the CLAUDE file
if there is one, otherwise the AGENTS file. Then show me what you added.

## Numbers in the UI
When a screen shows stats (stat cards, profiles, dashboards):
- Write each as label + value + one helper line, computed from real data only
- Make key numbers clickable tabs that open a small chart
- Chart only real history — under 4 data points, never invent sample data
- Reuse existing tab and chart components, no new dependencies
  • Step 2: Check the rule landed, Claude echoes back what it added. Then build any stats screen. Numbers get helper lines, key ones open a chart on click, and nothing gets faked.
