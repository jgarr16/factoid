Three features worth trying next

Hi John,

Three features worth trying once your first requests are landing. Each one is a single parameter change. Each one earns its place in production code and none of them require a new integration or a different endpoint.

See the feature docs

Streaming. Set stream=True and tokens arrive as they generate. Same endpoint, same auth, one parameter. Perceived latency drops from seconds to the first token, which is the difference between a chat UI that feels alive and one that feels broken. Agents that stream partial results to a frontend get a noticeable UX lift for zero code cost.

Structured outputs. Pass a JSON schema via response_format and OpenRouter enforces it at the API level. No regex parsing, no retry loops when the model returns malformed JSON, no "please respond in valid JSON" prompt engineering. Works on every model that supports the format, and the router respects it when you use openrouter/auto.

Provider preferences. Pin specific providers, exclude others, set latency floors and throughput minimums. When a model has multiple providers behind it, you decide which backend serves each request. Set {"sort": "price"} to always pick the cheapest, or an allowlist to lock routing to providers you trust.

ALL THREE AT ONCE

response = client.chat.completions.create( model="openrouter/auto", stream=True, response_format={"type": "json_schema", "json_schema": schema}, extra_body={"provider": {"sort": "price"}}, messages=[{"role": "user", "content": "..."}], )
