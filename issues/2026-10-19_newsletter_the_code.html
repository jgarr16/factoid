INSIGHT

Meta's engineering team shows how to verify agent output

Source: The Code, Superhuman

Eight weeks, one small team. Meta’s engineers gave an AI agent a bigger job than writing code. It helped plan, build, and test Forum, a standalone Groups app that reached core feature parity with Facebook Groups in that time. Most importantly, the team created a clear process to verify the agent's work before shipping.

Show your work. Getting code to compile was only the start. Meta counted a change only once it was verified and production-ready. The setup comes down to three moves any team can copy:

  • Raise the finish line. A task is done only after it passes automated tests and visual checks.

  • Let the agent check itself. Run your build checks, unit tests, and UI comparisons directly inside the loop. That way, the agent catches and fixes its own mistakes before anyone else sees them. You end up reviewing fewer pull requests, and the ones you do get are actually ready to ship.

  • Attach the proof. Every pull request includes a test plan and a recording of the verification run, making sign-off simple.

Trust has a test suite. The more Meta trusts those checks, the more work it can safely hand over. Routine stress tests during development caught a memory issue. The agent reproduced the problem, fixed it, and verified the result, roughly halving memory use and page faults before the app reached users.

Green isn’t golden. Passing every automated check does not guarantee good code. Meta learned that test suites must actively catch shortcuts, because faster runs cannot fix weak evaluation signals. Today, engineers still review and approve every shipped change while working toward full autonomy. Ultimately, giving agents more ownership starts with building foolproof ways to verify their work.
