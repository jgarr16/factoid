INSIGHT

Tech companies are building “internal vibe-coding apps.” Here’s why:

Source: The Code, Superhuman

A new kind of in-house tool. A growing number of tech companies are building in-house AI app builders for non-technical employees. Gergely Orosz, a former Uber engineering manager and the writer behind the popular newsletter The Pragmatic Engineer, set out to understand why. He visited Ramp's New York office and looked into a similar tool at Stripe, uncovering a quiet shift in who builds software at work.

What he saw inside. At Ramp, nearly every non-engineer uses Glass, the company’s own take on the AI app builder Lovable. Staff build tools for their own work, then share them so colleagues can use and change them. One marketer even built a custom CRM. Glass is now so central that building a simple tool in it is part of onboarding for new hires.

Why not just buy one? That raises an obvious question, since tools like Lovable and Replit already exist. For Orosz, the answer mostly comes down to control. An in-house tool can safely use company data that would be risky to share with an outside vendor, and it follows the company’s own design rules. It’s also cheap: Stripe’s version, Harbor, took one engineer about six weeks.

The payoff goes beyond the tool. Building these platforms also gives engineers hands-on AI experience, a skill that is tough to hire for right now. Factor in the low cost and high adoption, and Orosz expects plenty of tech companies to follow suit. How to read AI-written code like a senior engineer

Claude Code can write multi-file changes faster than you can review them, but you still have to sign off before merging. This GitHub repo closes that gap by using Claude Code to turn any git diff into an interactive, guided walkthrough, just like a senior engineer would read it.

  • Step 1: Install diff-tour. You need git and a signed-in Claude Code, Codex CLI, or Gemini CLI.
curl -fsSL https://raw.githubusercontent.com/init-co-jp/diff-tour/main/install.sh | sh

  • Step 2: Run “cd your-repo” and “tour” from your project, replacing “your-repo” with your project folder. On the first run, press Enter twice to accept the default language and LLM, then press Enter again to tour your current branch.

  • Step 3: Move through the tour with → and ←. Claude Code takes 2 to 5 minutes to write it with read-only access, then explains what the change is for, splits must-fix from nice-to-have, and asks you questions before showing answers. Press ? to ask your own.

  • Step 4: Hand the must-fix items back to Claude Code, replacing the bracketed list.

diff-tour flagged these must-fix items: [paste list]. For each one, tell me how you plan to fix it and which files you'll touch, and wait for my OK before changing anything. After fixing, run the tests and tell me which items are fixed and which aren't.
