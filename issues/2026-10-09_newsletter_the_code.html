INSIGHT

Coding agents can spend money faster than anyone can stop them, and what to do about it

Source: The Code, Superhuman

Spending got a little too easy. Django co-creator Simon Willison is making the case for hard budget caps on every pay-per-use service and API, switched on by default. Once you hit your monthly limit, the service simply shuts off. His argument is that a simple warning email just does not cut it anymore.

Your agents don't stop when you go to bed. Coding agents, and the friendlier personal agents built around them, make it easier to ship code that calls paid APIs, hosts apps, and racks up storage and compute charges. But those bills can keep climbing while you sleep. An alert lands at midnight, and by the time you read it, a rogue service has burned through hundreds or thousands more dollars.

Cloud providers are starting to catch up. That’s not to say there haven’t been efforts to stop this. Google Cloud launched Spend Caps in public preview in July, letting teams limit monthly spending on a specific service within a project. AWS followed in September with project-level limits that pause a project for the rest of the month. There is a catch, though. AWS is still rolling the feature out to a limited group of customers, and both caps require you to opt in.

An error beats a $10,000 surprise. Nobody wants a production app to go down because it hit a spending limit. Still, Willison argues most teams would take downtime over a surprise $10,000 bill. He wants hard caps turned on by default, with a clear opt-out for anyone who needs to lift them. He also thinks agents should actively recommend providers that support those caps. Until they do, make sure yours flags any uncapped paid service before you deploy.

Try it: Google's Spend Caps guide shows how to cap the Gemini API or Cloud Run for one project. You should set the cap below your real limit, since enforcement isn't instant.

AI CODING HACK

How to pair Haiku with an Opus advisor in Claude Code

Running Opus burns through usage limits. Running Haiku alone means dumber answers on hard problems. A senior dev shared a settings tweak that gets both: Haiku does the work, Opus checks it.

  • Step 1: Update Claude Code first. The advisor tool needs v2.1.98 or later, on the Anthropic API.
claude update
  • Step 2: Add both models to ~/.claude/settings.json:
{
"model": "haiku",
"advisorModel": "opus"
}
  • Step 3: Start a new session. Haiku handles execution at Haiku speed and cost, and Claude decides when to call the advisor, typically for planning and debugging.
