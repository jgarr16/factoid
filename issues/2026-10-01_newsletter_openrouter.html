What shipped on OpenRouter in September

Jev Router launched on September 25. Set the model to typesafe/jev-router and it picks a model and a reasoning effort for each request, balancing quality, speed, and cost, across a catalog that now includes GPT-6 Sol, Grok 4.7, and Gemini 3.8 Flash.

Claude Opus 5.5, Claude Fable 5.1, and GPT-6 Astra, all September launches, now hold the top three places on the Intelligence Index, on the benchmarks board. OpenRouter also released the self-serve Business plan with US and EU in-region routing. The Batch API is live with per-model discounts, typically 50% off, and any tool-calling model can now use a hosted shell.

Try Jev Router in Chat

New router

Jev Router picks the model and effort for each request

Jev Router runs on Jev, TypeSafe's decision model. Before each turn, Jev scores the prompt on difficulty and precision, and checks whether a bigger model or more effort would help, whether a cheaper model is enough, and whether the task changed.

It keeps a model that works for the rest of the session and raises or lowers effort without switching, so the conversation stays in the cache. It switches only when the expected gain is larger than the cost, including the cache it would lose. Each response includes routing metadata with the reason for the choice, and the routing insights panel in OpenRouter Chat shows the model and the scores behind every turn.

Jev reads only the conversation text, never attachments, under zero data retention terms, and requests with zdr: true work with Jev Router. If the Jev call times out or returns invalid output, the request fails instead of falling back to another router. Read about Jev Router.

In-region routing

Choose where your inference runs

Data residency, previously the line between a self-serve account and a sales conversation, is now a base URL. Point a request at us.openrouter.ai or eu.openrouter.ai and OpenRouter decrypts, routes, and serves it inside that region, on the same API key and the same model IDs. If no in-region provider can serve the model, the request returns a 404 instead of quietly leaving the region, and openrouter/auto and other router models are not available on regional domains.

curl https://us.openrouter.ai/api/v1/chat/completions \ -H "Authorization: Bearer $OPENROUTER_API_KEY" \ -d '{ "model": "anthropic/claude-fable-5.1", ... }'

One line changes: point a service at the regional base URL and leave the rest of your traffic on openrouter.ai. To enforce it, set a guardrail's allowed data regions for a key, a member, or a whole workspace, and OpenRouter rejects that key's, member's, or workspace's requests when they arrive through any other domain. The models page filters to EU-eligible and US-eligible models.

It ships with the Business plan, which any account or organization switches on from its settings, and with Enterprise. The fee is 8% on credit purchases, against 5.5% on Standard; both plans bill inference at provider rates, with no monthly minimum or contract. Business also raises the workspace cap to 1,000. The model behind it

Jev answers typed questions, and your code acts on the answers

typesafe/jev-1.13 is live on OpenRouter through the System One API. It is a decision model from TypeSafe, and it does not generate text. You send a state (a message, a document, a pending tool call) and typed questions, and it returns typed answers your code can branch on, with a median round trip of 0.24 seconds on OpenRouter.

Jev answers three question types: noul (yes or no), choice (pick one option), and score (a number in a range). Choice and score answers can also carry per-option probabilities and a confidence value, for code that wants to set its own threshold.

Jev reads instructions literally. Keep arithmetic and date comparisons in your code, and send only the state a question needs.

Teams already on the TypeSafe SDK switch by pointing their base URL at openrouter.ai/api and using an OpenRouter key. See the TypeSafe SDK guide.

Two cookbooks show where Jev fits in a pipeline: Gate agent tool calls with Jev and cut LLM cost with a Jev-verified cascade.

Batch API

Batch discounts, 24-hour window

The Batch API is live. Each batch uses one model and one endpoint shape: submit an inline array of requests and collect the results within 24 hours. It accepts chat completions, Responses, Anthropic Messages, and embeddings. Batch requests are typically billed at 50% of the model's per-token price; xAI models are 20% off in batch (Grok 4.3 at $1.00 / $2.00 against $1.25 / $2.50), and web search and prompt caching bill at their usual rates. Models with batch support list a :batch variant with the batch rate, for example openai/gpt-6-astra:batch at $5/M input. Batches are text-only.

POST https://openrouter.ai/api/v1/batches { "endpoint": "/v1/chat/completions", "model": "openai/gpt-6-astra", "requests": [ { "custom_id": "req-0001", "body": { ... } } ] }

The batch rankings page shows weekly usage of batch models across OpenRouter.

Server tools

A hosted shell for any tool-calling model

Add openrouter:shell to the tools array and any tool-calling model can run commands in a hosted Linux container. The model writes a script, runs it, reads stderr, fixes it, and then answers. openrouter:bash does the same for the Anthropic tool shape, and the Files API stores up to 10 GiB per workspace for containers to read and write.

Sandbox time costs $0.0001 per active second, billed inside the request. Both tools are in beta, and workspace admins can switch any server tool off. Read the announcement.

What the usage data shows

As of September 8, GPT-5.6 Luna was the only closed model in the top 10 by token volume over the prior 30 days, and number two overall.
