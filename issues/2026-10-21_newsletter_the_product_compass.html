1.1 Code tab vs. Cowork: why not Cowork?

Okay, but then why not Cowork? It’s also part of the new Claude Desktop, right?

Not exactly.

Cowork is an improved chat that works in a virtual machine. Unfortunately:

  • It won’t let you run and preview apps, create project-specific skills, declare project-specific app connections (MCP), or define guardrails.
  • It doesn’t support the AGENTS.md standard. Using the standard allows other agents, such as Codex or Muse Code, to work on the same projects.
  • Its virtual machine size is limited. In real work, you’ll quickly hit that limit (10GB). Going beyond that is painful - I ended up resetting my environment regularly.

2. How to Start With Claude Desktop

All you need to do is go to claude.com/download and get Claude for your OS. Claude Code is included, so you don't need to install anything else.

Next, sign in and switch to the Code tab. For that, you need a paid subscription (Pro, Max, Team, or Enterprise).

2.1 Pick a folder

Start with a session running on your local machine. On the new session page, select “This computer” and create a new folder:

📌 Folders are essential. They are containers for your work, with project-specific instructions (your AGENTS.md), knowledge, skills, and other settings.

2.2 Pick the permission mode

The permission mode decides when Claude asks before acting. Use Auto by default. Anthropic made it the default setting in Claude Code. Each action is evaluated by an independent agent:

2.3 Pick the model and effort

You can do it under the chat input:

My default recommendation right now:

  • Haiku 5.5: for most of the work if you're worried about budget. Unlike the previous Haiku, it's a very strong, cost-efficient model.
  • Sonnet 5.5: if your budget is $100 or $200 a month and only for simple tasks (e.g., subagents). For complex work, its price is similar to Opus 5.5’s (same cache reads and writes).
  • Opus 5.5: for the most challenging, strategic work.
  • Fable 5.1: don't use it. You pay much more for virtually the same experience.

📌 As for effort, I use High for almost everything. Claude thinks longer only when needed, and for simple tasks, it doesn’t make much difference. The exception is Opus 5.5, where I use Extra (xhigh). Never Max.

My recent benchmark with real, complex work below. Note that Haiku 5.5 (high) performed better than Opus 4.8 (high). It’s a really strong, efficient model:

Source: Bug Hunt Benchmark

I also recommend you avoid:

  • The “Enable fast mode” setting. In practice, it’s not way faster and burns many more credits.
  • “Ultracode” under the “Effort” settings unless you have a $200/mo subscription and know what you’re doing (e.g., broad research). It orchestrates multiple subagents, each doing significant work, and can consume your usage limits quickly.

2.4 Connect your apps

Before prompting, connect your apps. Click + in the message box and select Connectors. For most apps, you'll find one in the Claude directory. Those connectors are available in all your local sessions.

📌 Critically, you can also manage permissions for each offered tool under “Manage connectors.”

For example, Claude will ask me every time before drafting a message in Gmail:

You can also add a connector (an MCP server) to one project only, for example, when it shouldn't be available in other projects, or when it's a custom one the Claude directory doesn't have.

You don't have to learn how to install it. Just ask Claude in the chat, e.g.:

I want to start live Q&A and polls. Find and install an MCP server for AskOne.org. I want it to be available [in this project only / globally].

2.5 Browse skills and knowledge work plugins

📌 Skills are reusable instruction manuals that teach Claude how to approach specific, repeatable tasks. Plugins bundle skills with slash commands. We discussed skills, commands, and plugins in my Cowork guide.

You'll find many under Customize, e.g., Anthropic's knowledge work plugins, like Marketing, Engineering, or Finance:

Customize > Skills and Plugins in Claude Desktop

📌 Be careful with the skills. The ones you need the most (PDF, Word, spreadsheets, etc.) are already there. Before installing more, understand what you need.

The reason is that the description (front matter) of each installed skill is loaded into the context window. 10 is not a problem. 100 or 200 will cost tokens and can make your Claude dumber.

In the last section, I explain my workaround: how agents can use entire skill collections without being overwhelmed.

4.6 Long sessions: compact and rewind

Some people claim the cost of Claude grows linearly with the number of messages. That’s not true. First, a session starts big: its initial size can be about 40,000 tokens. Then there’s the cache. With every new message, you don’t pay the full price for the earlier ones again, because they’re read from the cache at a much lower cost.

Still, I recommend you compact after every major step (type ). Claude keeps only the basic information about what’s happened so far, without the details it can discard.

You can also use auto-compact. I recommend setting it to 300,000 tokens (). This is enough for most use cases. You don’t need 1 million tokens, and it will save you a lot of usage (cache reads and writes):

The auto-compact window is set per model, here for Opus 5.5

And rewind just works. Click your previous message and choose “Rewind to here” to start again from there:

5. Other Features: Nice, Not a Breakthrough

The update added a lot if you need to run many sessions in parallel. There are interesting use cases, but this isn't how most Product Managers will use Claude Desktop:

  • Nested sessions (Thariq calls them subsessions): ask for parallel work, and Claude starts a separate session for each task. Unlike subagents, you can open them, see the whole conversation, and steer them.
  • Side questions: type to ask a question in a separate tab while the main session keeps going.
  • Split view: Ctrl-click (⌘-click on a Mac) a session to see two side by side.
  • Source control: if your engineers work with Git, you can open the same project. Pick a branch, or a worktree (a separate copy for parallel work), in the folder menu.
