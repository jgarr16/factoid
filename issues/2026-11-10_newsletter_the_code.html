INSIGHT

5 questions to decide how much human review a PR needs

Source: The Code, Superhuman

PRs are piling up.Your agents can churn out code all day, but you are still stuck reviewing every line. The faster they work, the longer your review queue grows. Ben Holmes, who works on Warp’s agent factory, just published a playbook for clearing the backlog. He still wants humans signing off on every merge. His fix is to score each PR by risk so you know what actually needs your attention.

Five checks before you even open a diff.

  • Verification: Tests alone aren’t enough. Get your agents to attach screenshots or recordings showing before-and-after states. Make that evidence a required part of every PR.

  • Alignment: Did the agent actually build what you asked for? Check the code against the original issue and PR description. Any random fixes or unwanted extras should go.

  • Impact: What’s the worst that could break? Changes to auth, permissions, or billing need a code owner’s eyes. Break high-impact changes into smaller, stacked PRs.

  • Rollback cost: How easily can you undo the damage? Using Matt Pocock’s framing, label changes as two-way doors or one-way doors. Destructive schema migrations, for instance, need a proper rollback plan.

  • Error detection: If something breaks, will you even notice? Make sure errors reach a monitoring service. Warp even pipes Sentry alerts to its agents through webhooks so they can investigate their own bugs.

Let the agents triage. Warp has packaged these five checks into an open-source /merge-risk skill. Your agents can run it before handing over a PR and fix whatever gets flagged. Humans still make the final call, but there’s less digging to do. Holmes recommends starting with just two new fields in your PR template: “impact” and “rollback cost.”

AI CODING HACK

How to stop AI agents from bolting on features

Ask Claude Code or Cursor for a feature and it jams the code in wherever it fits. Do that ten times and the architecture rots. A dev shared a one-paragraph fix for this.

  • Step 1: Open the agent instructions file at your repo root. That’s AGENTS.md for Cursor and Codex, CLAUDE.md for Claude Code.

  • Step 2: Add this at the top:

Always build code cleanly, modularly, and with proper architecture
and separation of concerns. Never simply bolt on a feature because
I asked for it. If you can't find an easy way to build it naturally,
and you'd recommend a refactor to make the whole thing clean, stop
your work ahead of time and say so.

That last sentence does the work. Instead of forcing a bad fit, the agent halts and proposes the refactor first.
