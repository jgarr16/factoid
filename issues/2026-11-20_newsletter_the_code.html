INSIGHT

A developer tried to replace Claude Code with a local setup. Here’s what broke

Source: The Code, Superhuman

Agent Memory. AI coding agents are great until they get stuck on the same bug, pile on broken code, and forget what they were building. Smaller local context windows even make it worse. Veteran engineer David Gewirtz wanted to see if a free, local setup could replace Claude Code, so he ran an experiment. He paired OpenCode with Qwen’s coding model on a 128GB Mac Studio. No subscriptions or cloud involved, which sounds promising, except his agent had just 64,000 tokens of context, versus Claude Code’s million.

The Build. First came a PDF organizer built on a new macOS 27 feature the AI had never seen. It read one PDF but couldn’t handle a folder. Next, a tool to rename his 7,000+ screenshots. He spent four days fighting the file list, with failed fixes eating context until the agent lost track. He then deleted the broken code, opened a fresh session, and tried again. It worked.

Here are his rules worth stealing:

  • If your agent keeps failing at the same bug, stop piling on patches. Scrap the code and start fresh.

  • Give each feature, bug fix, or test its own conversation so old mistakes stay behind.

  • Have your agent save what it learns in a markdown file, then feed that file to a fresh session to code.

  • Pick the model yourself instead of letting the agent grab whichever one it finds first.

  • Keep shell commands behind manual approval. Your agent can delete files as easily as it creates them.

Hidden Costs. Gewirtz spent nearly two weeks on an app he reckons he could have hand-coded in a few evenings. Free local agents can handle small projects, but long debugging sessions break them. If you’re ready to try it for yourself, Ollama’s OpenCode guide sets up the same stack with one command.
