Why Gumloop’s CTO stopped babysitting coding agents and built a factory instead

Five VMs, one problem. Gumloop’s AI agents had gotten slow to start, and users noticed. CTO Rahul Behal then opened five VMs and asked a coding agent in each one to find the cause. Before he finished setting up the fifth, the first came back with a fix. Most of the time, the agents were right. So why was he still in the middle?

Enter the factory. That experiment became the basis of Gumloop’s Software Factory, where agents handle the repetitive work and engineers focus on what actually needs their attention. Here’s the playbook in six steps:

  • Pick easy wins. Start with bugs, slow endpoints, or platform tasks where the fix is easy to verify.

  • Give tasks their own lanes. Split work into production lines, each owned by the engineer who knows it best.

  • Ditch the busywork. Scheduled triggers or a quick ping open Linear tickets for you.

  • Let agents manage agents. A Gumloop worker reads your team’s skills and conventions, then sends the task to a coding agent.

  • Demand receipts. Every PR needs proof, like a test that fails before the fix and passes after. You still get the final say on merges.

  • Answer once, reuse forever. Agents ask the line owner in Slack for decisions and remember the answer.

The scoreboard. In six weeks, engineers merged 571 agent-written PRs. P99 agent start times dropped from 24.9 to 4.5 seconds, and 83% of closed agent-written PRs needed zero human code changes.

Write it down. Gumloop wrote or updated 94 skills in five weeks, and no-human-edit merges jumped from 57% to 89%. The more you document your team’s decisions, the less you have to babysit agents. The full breakdown goes deeper, from Slack judgment calls to adding Devin after a Cursor outage.

How to catch mobile bugs before your users do

A design engineer shared a QA prompt that fixes a common failure: AI-built frontends look fine on your desktop and fall apart on a phone with bad signal.

  • Step 1: First, give Claude Code a real browser. Install the Chrome DevTools MCP server
claude mcp add chrome-devtools -- npx chrome-devtools-mcp@latest
  • Step 2: Start your dev server, then paste this prompt
Test this in the browser at different widths, with touch emulation, and on a throttled 3G connection. Fix anything that looks broken or feels off. Save a before and after screenshot for every fix and send me a summary afterwards.

Claude opens the app, resizes the viewport, throttles the network, patches what breaks, and hands back before/after screenshots as receipts. The same MCP works in Cursor and Gemini CLI.
