INSIGHT

A Stripe engineer's advice for junior developers

Source: The Code, Superhuman

AI already has a head start. New engineers used to learn by writing code, fixing bugs, and reviewing PRs. Now AI does much of that for them. Vikram Singh, a Stripe engineer who joined as a new grad about 18 months ago, wrote a guide on getting good anyway. He claims that GPT-6 beats a new hire on day one at understanding the domain, writing code, and reviewing it.

Slow down. AI can find answers, write code, and solve problems so quickly that it’s tempting to let it do all the thinking. Singh warns that while this might make you productive today, it could hold you back in the long run. You risk becoming a “meat proxy” for the model, a term he borrows from Niklas Gruhn. He advises slowing down during those first few months while expectations around your output are still low.

Understand the code. Singh’s benchmark is HashiCorp co-founder Mitchell Hashimoto’s “whiteboard defense”: engineers should be able to walk someone through any customer-facing system they’ve shipped and justify their decisions. To get there, Singh suggests a few habits:

  • Run coding agents inside an IDE so you can see every change. Singh found Cursor particularly useful for learning.

  • Don’t ship code you can’t explain or defend.

  • Take code reviews seriously, and use them to understand each change.

Know what you’re doing. Singh uses LLMs for most of the “what” questions and saves his colleagues’ time for the “why.” Why was a system built this way? Is this even the right approach? Once you understand the problem, AI can make the actual coding much easier. His bigger point for junior devs and the teams hiring them is that time spent learning early is what makes you genuinely faster later.

AI CODING HACK

How to decide if you need a software factory

Everyone’s pitching autonomous agent pipelines, but nobody tells you whether your team actually needs one. Senior dev Matt Pocock shared a prompt that settles it, built on his new /software-factory skill which is a glossary for factory design.

  • Step 1: Install his skills repo. Pick “grill-me” and “software-factory” in the installer:
npx skills@latest add mattpocock/skills
  • Step 2: Restart Claude Code, then run the prompt:
/grill-me on how a /software-factory might help us

Claude interviews you one question at a time against the factory glossary, then brainstorms the infra you’d need to set one up. The skill ships with research docs on orchestrators, git hosts, ticket trackers, and runners.
