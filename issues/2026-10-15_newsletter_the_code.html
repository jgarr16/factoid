How Atlassian built its AI software development lifecycle

Source: The Code, Superhuman

Every agent starts as a new hire. Your coding agent can rewrite a service in minutes. It just doesn’t know why your team swore never to touch it again. The architecture debates, abandoned fixes, and decisions buried in old docs all shape good code. Atlassian’s AI SDLC transformation playbook argues agents need that backstory supplied, and its internal results point to better answers on fewer tokens.

The fix is a map. Atlassian built the Teamwork Graph to give agents that background on every task. The design choices behind it are worth copying:

  • Connect the backstory to the code. Link tickets, docs, decisions, and recordings so an agent can trace why a service looks the way it does. Atlassian’s graph does this across Jira, Confluence, Loom, and 50+ sources.

  • Meet agents where they work. Expose that context through MCP or a CLI, so agents can pull it from the terminal or IDE.

  • Gate access at the data layer. Enforce permissions on the data itself, so an agent only reaches what its user can see.

  • Write every session back. Feed agent and human activity into the graph, so each task leaves more context for the next one.

Atlassian has receipts. In internal benchmarks, agents with graph access were 44% more accurate while using 48% fewer tokens. Atlassian also notes that each run gets better and cheaper. The playbook's first two steps work across any stack which is to anchor on context, then measure before you scale. If your team wants to grade its own context, this guide is a good place to start.

AI CODING HACK

How to get better Codex memory for your projects

Codex’s memory feature writes and merges your session memories with GPT-5.6 Luna and GPT-5.6 Terra by default and not its best models.

A senior engineer shared a two-line config fix that routes memory through GPT-6 class models instead.

  • Step 1: Open Codex’s config file by typing this command:
open ~/.codex/config.toml
  • Step 2: Find the memories section (add it if missing) and pin the upgraded models.
[memories]
generate_memories = true
use_memories = true
extract_model = "gpt-6-luna"
consolidation_model = "gpt-6.1-sol"

  • Step 3: Restart Codex. The “extract_model” setting now handles per-thread extraction, while “consolidation_model” manages the global merge. As a result, your new memories will become noticeably sharper over the next few sessions.

  • One trade-off is that bigger models use more of your rate limit during background generation. You can find the full list of settings in OpenAI's config reference.
