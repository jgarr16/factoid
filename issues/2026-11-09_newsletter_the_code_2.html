INSIGHT

So AI writes most of your code. Here are 4 skills to set yourself apart.

Source: The Code, Superhuman

Speed has a catch. Agents can now write in minutes what once took weeks, but that speed brings a whole new challenge. And that’s figuring out what is actually worth building. Director of Engineering at Cloudflare, Christoph Nakazawa, knows this firsthand and says he barely writes code himself anymore and that AI wrote 90% of his recent projects. In his updated essay on Modern Engineering Values, he explains what still makes a good engineer when agents match or beat his own code.

It comes down to four values that matter whether you’re working with humans or AI:

  • Strong ownership: Agents amplify ownership, so if you know your product inside out, you’ll ship faster. Without that understanding, you’ll just create more noise. Nakazawa prefers small teams of two or three, with clear responsibilities and separate repos.

  • Taste and strict guardrails: Agents let you build almost anything, and hence good taste helps you pick what’s worth building. Alongside, strict guardrails help agents get it right. Lint rules, automated tests, and checks on changed files can mean the difference between finishing in a minute or an hour.

  • Context in the repo and an owned stack: Every new agent session starts from scratch, and agents can’t reach knowledge scattered across Notion, commit messages and people’s heads. Put it in the repo instead. Nakazawa even built his own JavaScript stack, arguing agents make owning core code far more practical.

  • Option value: Every change should open up more possibilities for the next one. AI can rewrite huge chunks of code fast, but that won’t help if you’ve vibed yourself into a corner.

The real bottleneck according to Nakazawa now is exercising judgment. And with software shipping this fast, he believes we’ll need engineers more than ever. For a deeper dive, check out his Principles of Developer Experience.

How to untangle the state logic in a messy project

Messy codebases end up with implicit state machines everywhere, like random booleans, flags, and status strings scattered across files that inevitably break when one changes. A dev shared a quick one-prompt fix for Claude Code or Codex.

  • Step 1: Commit first, so the refactor is one command to undo:
git add -A && git commit -m "pre-refactor checkpoint"
  • Step 2: Open Claude Code in the project root and paste:
Find all of the implicit state machines in my app. Make the best decision that will elevate all three: the user experience (UX), developer experience (DX), and agent experience (AX) always, without breaking anything.

Claude maps the hidden flags into explicit states, then refactors them.

  • Step 3: Review the diff before accepting. “Without breaking anything” is an instruction, not a guarantee, so run your tests after.
